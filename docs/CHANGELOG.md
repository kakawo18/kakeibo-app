# 変更履歴

変更を入れたら `package.json` の `version` を更新し、このファイルの先頭に節を追加する（運用ルールは `AGENTS.md` の「バージョン管理」を参照）。

## [6.5.0] - 2026-08-31

### 追加
- **振り返りタブに「カテゴリ別支出の内訳」の円グラフを追加**: ホームの月次の内訳と同じ見せ方で、選んだ年の1年分を表示する
  - 年間の合計は桁数が多く中央に収まらないため、中央を塗りつぶした円グラフにして合計は出していない（合計は上のタイル「年間支出」で読める）
  - カテゴリ数が多いと引き出し線ラベルが密集するので、扇は「その他」を含めて6つまでにまとめる

### 改善
- **カテゴリ別支出の前年比を横棒グラフにした**: 差額だけを左右に伸ばす独自の表示は、金額の大小が読み取れず見にくかった
  - 1カテゴリにつき前年・今年の棒を2本並べ、今年の棒の右端に増減額を出す（増えた＝支出色、減った＝収入色）
  - 表示は差の大きい上位8件
- **円グラフの引き出し線ラベルが重ならないようにした**: 小さい扇が固まると2つ以上のラベルが同じ高さに並んで文字が潰れていた。左右それぞれで上から間隔を空けて配置し直す。ホームの内訳グラフにも効く

## [6.4.0] - 2026-08-30

### 追加
- **カテゴリの役割に説明を表示**: 設定 → カテゴリの編集画面で、各役割の下に「この役割を付けると集計がどう変わるか」を1行で表示する。ラベルだけでは何が起きるか分からなかった

### 改善
- **「カード引き落とし」の役割を廃止**: カード支払い分との二重計上を防ぐための仕組みだったが、現在は使われていない。設定画面の選択肢から消え、新しい取引に付くこともなくなった
  - 過去の取引の集計結果は変わらない。集計から外れるかどうかは `affectsExpense` が決めており、この役割とは別に取引ごとに保存されているため
  - 取引一覧の「引落」バッジは、過去の取引を説明するために残している
  - **既存ユーザーの設定にある「カード引き落とし」カテゴリは自動では消えない。** 不要なら設定ページで削除すること。残したまま新しい取引を記録すると、通常の支出として集計される

## [6.3.0] - 2026-08-30

### 改善
- **カレンダーの日別内訳を、画面下から出すシートからカレンダーの下の欄へ変えた**: シートが画面の6割を覆っていたため、月の後半を選ぶには結局いったん閉じる必要があった。カレンダーに一切被らない位置に置くことで、月内のどの日でも開いたまま選び直せる
  - 前日／翌日ボタンと、閉じるボタンはそのまま
- **カレンダーの日別内訳の見た目を履歴タブのリストと揃えた**: 同じ取引が場所によって違う見た目になっていたのをやめ、行の描画を `TransactionRow` に集約して両方で共用する。カレンダーの内訳からも取引を編集・削除できるようになった
  - 大きなカードを並べる形から、履歴タブと同じ1行の台帳表示に変更。1件あたりの高さが下がり、日別内訳全体が縮んだ
  - 収入／支出／収支を並べたサマリーカードは廃止。履歴タブの日付ヘッダーと同じく、見出しの右に日次の収入・支出だけを出す（収支はカレンダーのセルに出ているため）

## [6.2.0] - 2026-08-30

### 改善
- **カレンダーの日別内訳を閉じずに日付を渡り歩けるようにした**: これまでは1日を開くと × で閉じないと他の日を見られなかった
  - 内訳の見出しに前日／翌日のボタンを追加（移動できる範囲は画面に出ている42日ぶん）
  - オーバーレイをやめ、背後のカレンダーをそのまま操作できるようにした。見えている日付をタップすると内訳が開いたまま中身だけ切り替わる

### 修正
- **初期設定で配当収入が給与収入として数えられる**: `配当収入` が `salary_income` を持つ `給与` カテゴリのサブカテゴリになっていた。`hasRole` は「カテゴリ **または** サブカテゴリに役割があれば true」という実装のため、サブカテゴリ側では役割を打ち消せず、配当金が貯蓄率の分母に入り額面推定の対象にもなっていた（配当を給与とみなして社会保険料・所得税を逆算するため額面が過大に出る）。`その他` カテゴリのサブカテゴリへ移した
  - 既存ユーザーの設定は自動では変わらない。設定ページで `配当収入` が `給与` の下にある場合は `その他` へ移すこと

## [6.1.1] - 2026-08-29

### 修正
- **テーマ切り替えが初回だけ2回タップしないと効かない**: `useMantineColorScheme().colorScheme` はユーザーが明示的に選ぶまで `'auto'` のままで、これを `'dark'` と比較していたため、OS がダークでも「今はライト」と誤判定していた。1回目のタップが「すでにその見た目」への切り替えになって何も起きていなかった。`useComputedColorScheme` で `'auto'` を実際の light/dark に解決するようにした
- **ダークモードでチャートやカテゴリ色がライト用のまま出ることがある**: 上と同じ原因。円グラフ・カテゴリ別支出推移・取引履歴・設定のカテゴリ一覧が、OS のダーク設定に追従していなかった（テーマを一度手動で切り替えると直る状態だった）
- **下部タブバーが iOS のホームインジケータに近すぎる**: ラベルの下に余白が無く、タブを押すときにシステムのスワイプ操作を誤爆しやすかった。アイコン行の高さ（`--tabbar-content-height`）とホームインジケータ避けの余白（`--tabbar-bottom-gap`）を分けて持ち、ラベルの下に 12px 空けた

## [6.1.0] - 2026-08-29

- **月移動の専用行をなくした**: 月の切り替えだけで1行ぶんの高さを使っていたのをやめ、既存の行に同居させた
  - ホーム: 収支カードの見出し行に「‹ 2026年08月 ›」と「年間振り返り ›」を並べる。カード全体のクリックはやめ、振り返りへの導線はリンク部分だけにした（中に月移動のボタンがあるため）

- **ホームと履歴を左右スワイプで月移動できるようにした**: カレンダーと同じ操作感。画面のどこをスワイプしてもよい

- 縦方向のスクロールを殺さないよう `touch-action: pan-y` と framer-motion の `dragDirectionLock` を併用

## [6.0.0] - 2026-08-29

### 改善
- **アプリ構成をタブナビゲーションに刷新**: 縦スクロール1本だったダッシュボードを、目的ごとの4タブに分割した (#83)

- **履歴タブを新設**: 取引リストとカレンダーを1つの画面にまとめ、上部で切り替える。どちらも「取引を見る」同じ目的なので、探す場所を2つに分けない

## [5.3.0] - 2026-08-29

### 追加
- **年間振り返り画面 (/review)**: 年をまたいで見返すための新しい画面。ダッシュボードのヘッダー（モバイルは三点メニュー）と「今月の収支」カードから開ける。PWA のショートカットにも追加
  - **年収の推移**: 手取り + 社会保険料 + 所得税 + 住民税 の積み上げ棒。棒全体の高さが額面になる
  - **支出と投資の推移**: 支出と投資の積み上げ棒に手取り収入の線を重ね、手元に残った分が読めるようにした
  - **貯蓄率の推移** と **累計投資額（元本）の推移**
  - 年を選ぶと **手取りの使い道**（支出/投資/残りの内訳）、**カテゴリ別支出の前年比**、**月別内訳** を表示
  - 「年収の推移」「支出と投資の推移」は、棒の上に合計を表示し、グラフの下に内訳の金額テーブルを置く（グラフからは金額そのものが読み取れないため）。凡例と同じ色見本を見出しに付けて系列と対応させる
- **額面年収の推定**: 記録している手取りから、社会保険料・所得税・住民税を年分ごとの料率で計算して額面を逆算する。料率と控除額は `src/utils/tax/rates.ts` に集約し、2024年以前 / 2025年 / 2026年の3世代に対応（2025年・2026年の「年収の壁」改正で基礎控除と給与所得控除が大きく変わったため、年を無視すると数十万円ずれる）
- **年次集計のユーティリティ**: 各コンポーネントに散っていた年集計を `src/utils/annualSummary.ts` の純関数に集約

### 改善
- **年間収支モーダルを廃止し、年間振り返り画面に統合**: このモーダルだけ「年間支出に投資を含める」という他と食い違う定義を持っていた。新画面では支出（投資除く）と投資額を常に別々に表示する

### 技術的変更
- グラフの系列色を `globals.css` のトークン（`--series-*`）として追加。意味が固定された系列（社会保険料・所得税など）はユーザーのカテゴリ色と混ざらないようにした
- 年間振り返りの全グラフで Recharts のアニメーションを無効化。データの件数が変わる再描画（読み込み中の空配列 → 取引到着）で補間が破綻し、棒や面が描画されないままになるため

## [5.2.0] - 2026-08-17

### 追加
- **Firestore セキュリティルールをリポジトリで管理**: `firestore.rules` を追加し、`firebase.json` から参照する。取引（トップレベル `transactions`）は自分の `userId` のドキュメントのみ読み書き可、所有者の付け替えを禁止、未定義パスは全拒否 (#65)
- **セキュリティヘッダー**: `X-Frame-Options` / `X-Content-Type-Options` / `Referrer-Policy` / `Permissions-Policy` / `HSTS` を全ページに付与。CSP は Report-Only で導入（動作確認後に強制へ切り替える） (#68)
- **Firebase App Check の任意対応**: `NEXT_PUBLIC_RECAPTCHA_SITE_KEY` を設定すると有効になる。未設定時は初期化しない (#69)
- **CSV インポートの上限と検証**: ファイル 2MB・5000行の上限、日付/金額/種別/カテゴリの検証、メモ200文字への切り詰め。スキップした行数と理由、設定に無いカテゴリを結果に表示する (#70)
- **Dependabot**: npm の更新を毎週チェックする (#67)

### 改善
- CSV インポートを 500 件ずつの `writeBatch` に変更（1件ずつの書き込みをやめ、往復回数を削減） (#70)
- 新規登録時のパスワードを 10 文字以上に引き上げ（既存アカウントのログインは従来どおり） (#66)

### 修正
- **CSV エクスポートの数式インジェクション対策**: `=` `+` `-` `@` で始まる値の前に `'` を付ける。インポート時に元へ戻すため往復しても値は変わらない (#71)
- **ログイン画面のアカウント列挙**: 「未登録」と「パスワード違い」でメッセージを分けていたのを統一 (#66)
- **本番ビルドでの情報漏れ**: 取引データそのものをコンソールに出力していた箇所を修正し、本番では `console.error` 以外を除去 (#72)
- **Service Worker のキャッシュ範囲**: 自オリジンの正常応答のみをキャッシュするよう変更（ドメイン名の文字列一致による判定をやめた） (#74)
- `next.config.ts` の未使用 `env: { CUSTOM_KEY }` を削除（秘密情報がクライアントへ混入する入口） (#73)

### 技術的変更
- 依存関係の既知の脆弱性 17 件（critical 3 / high 11）を解消。Next.js を 16.3.1 に更新 (#67)
- `docs/deployment.md` / `AGENTS.md` のセキュリティ記述を実装に合わせて更新
