## 1. 認証

| 項目 | 内容 |
|---|---|
| 方式 | Firebase Authentication（メールアドレス + パスワード） |
| 新規登録 | メールアドレス・パスワード（10文字以上）で登録 |
| ログイン | メールアドレス・パスワード（6文字以上。10文字未満で作られた既存アカウントを締め出さないため、新規登録より緩い） |
| バリデーション | メール形式チェック、パスワード長チェック |
| エラー表示 | Firebase のエラーコードを日本語メッセージに変換して表示。「アカウント未登録」と「パスワード誤り」は同一メッセージにまとめ、アカウントの存在を外部から推測できないようにする |
| ログアウト | ヘッダーのメニューから実行（`AuthContext` 経由） |
| セッション | Firebase Auth の永続セッションに従う（明示的なタイムアウト設定はなし） |
| ログイン中の表示 | ヘッダーのアプリ名の下に、ログイン中のメールアドレスを表示する |

未認証状態で `(tabs)` 配下の画面を開こうとすると、`(tabs)/layout.tsx` の認証ガードによりログインフォームが表示される。

### 1.1 エラーメッセージ一覧

| Firebase エラーコード | 表示メッセージ |
|---|---|
| `auth/email-already-in-use` | このメールアドレスは既に登録されています。ログインをお試しください。 |
| `auth/invalid-email` | メールアドレスの形式が正しくありません。 |
| `auth/weak-password` | パスワードが弱すぎます。6文字以上で設定してください。 |
| `auth/too-many-requests` | 試行回数が多すぎます。しばらく時間をおいてお試しください。 |
| `auth/network-request-failed` | ネットワークエラーが発生しました。接続を確認してください。 |
| `auth/invalid-credential` / `auth/user-not-found` / `auth/wrong-password` | メールアドレスまたはパスワードが正しくありません。 |
| 上記以外 | エラーが発生しました。もう一度お試しください。 |

### 1.2 未対応

パスワードリセット、メールアドレス確認、アカウント削除、メールアドレス変更は画面から行えない（[`基本仕様書.md`](./基本仕様書.md#102-未対応の認証機能) 参照）。

## 2. 取引の記録・編集・削除

### 2.1 入力項目

| 項目 | 必須 | 備考 |
|---|---|---|
| 種別（収入/支出） | ✓ | 収入では支払方法欄が非表示になる |
| 金額 | ✓ | 円単位、小数点以下切り捨て |
| カテゴリ | ✓ | 設定済みカテゴリから選択 |
| サブカテゴリ | – | 選択したカテゴリに紐づくサブカテゴリから選択 |
| 日付 | ✓ | 既定値は当日 |
| 説明（メモ） | – | 自由入力 |
| 支払方法 | – | 支出のときのみ表示。任意（未指定なら現金扱いとして `normal` になる。[2.3](#23-取引タイプとフラグの自動導出)） |

**バリデーション**（クライアント側、送信時に判定）

| 項目 | 条件 | エラーメッセージ |
|---|---|---|
| 金額 | 入力済みかつ 0 より大きい | 正しい金額を入力してください |
| カテゴリ | 空でない | カテゴリを選択してください |

- 金額の上限はクライアントでは設けていない（Firestore ルールは `0 以上の number` のみ検証）。CSV インポートの上限（10億円）とは異なる点に注意。
- 日付の範囲制限は無い。
- 新規作成時の既定値: 種別=支出、日付=当日、その他は空。編集時は既存の値を初期表示する。
- 編集時、設定から削除済みのカテゴリ / サブカテゴリ / 支払方法が取引に残っている場合は、その値を選択肢の末尾に注入して現在の選択が消えないようにする。
- **任意項目を空に戻した場合**: メモは空文字で保存され消える。一方、サブカテゴリ・支払方法は空値が更新データから省略されるため、**編集で空にしても Firestore 上の既存値は消えず残る**（現状の制約）。

### 2.2 操作

- **追加**: ホーム・履歴タブに表示される FAB（＋ボタン）からモーダルを開いて入力する。
- **編集**: 履歴タブのリスト、またはカレンダーの日別内訳で対象行をタップして編集モーダルを開く。
- **削除**: 行右端のゴミ箱アイコンから。「この取引を削除しますか？この操作は取り消せません。」の確認ダイアログを経て物理削除する（[17. 共通仕様](#17-共通仕様通知確認ダイアログローディング) 参照）。
- **保存結果の通知**: 成功時は「取引を追加しました / 更新しました」（緑）、失敗時は「取引の保存に失敗しました。もう一度お試しください。」（赤）。失敗時はモーダルを閉じず、入力内容を保持する。
- **モバイルでの種別切替**: 入力モーダル内を左右にスワイプすると収入⇄支出が切り替わる。種別を切り替えるとカテゴリ・サブカテゴリの選択はクリアされる。
- **フォームの実装上の注意**: 金額・メモは非制御（uncontrolled）モードで扱う。PWA で1文字ごとの再レンダリングが入力イベントに追いつかず数字が重複する事象を避けるため。

### 2.3 取引タイプとフラグの自動導出

取引保存時、`category` と `paymentMethod` から `transactionType` と `affectsExpense` を自動導出する（ユーザーが直接指定する項目ではない）。

- 支払方法が「現金扱い」に設定された方法、または未指定 → `transactionType: 'normal'`
- 現金扱いでない支払方法（クレジットカード） → `transactionType: 'card_payment'`
  - **注意**: この判定は支払方法が設定画面に登録済みかどうかを問わない。「現金扱い」の名前一覧に含まれない文字列であれば、未登録の支払方法名でもカード扱いになる（CSVインポートで未知の支払方法名が来た場合に取引タイプの判定を変えないための互換動作）。
- いずれの場合も `affectsExpense: true` がデフォルト（役割による除外は集計時に別途判定する。[3. カテゴリ・役割](#3-カテゴリ役割) 参照）

`card_withdrawal` は過去に存在した役割「カード引き落とし」が生成したレガシー値で、新規取引には付与されない（[基本仕様書](./基本仕様書.md#81-transactionstransactionid トップレベルコレクション) 参照）。

### 2.4 クレジットカード払いの会計モデル（重要な業務ルール）

カード払いは**購入月に支出計上**する。ホーム画面の「収支」（選択月の収入−支出、[6. ホーム画面](#6-ホーム画面ダッシュボード) 参照）は月次集計から計算され、カード払いも購入月の支出として即座に反映される。

例: 6月にカードで1,000円支払うと、6月の支出に1,000円計上され、6月の収支は−1,000円になる。実際にカード代金が口座から引き落とされる7月には、支出としては再計上しない（6月で計上済みのため、二重計上を避ける）。

> **注意（用語の整理）**: 本アプリは実際の銀行口座の残高（現金がいつ動くか）そのものは記録・計算しない。「購入月に支出計上する」というのは、実際に使った月で支出の傾向を把握できるようにするための会計方針であり、口座から引き落とされるタイミング（実際のお金の動き）とは意図的に切り離している。「口座からの引き落としは翌月」という感覚は現実の口座の動きを説明しているだけで、アプリが計算・表示する値ではない点に注意する。

## 3. カテゴリ・役割

### 3.1 カテゴリ管理

- 支出／収入カテゴリを追加・編集・削除・並べ替えできる（設定画面）。
- カテゴリごとにサブカテゴリを複数登録できる（カテゴリ編集モーダル内で名前と役割を設定する。サブカテゴリ単位の色選択・並べ替え UI は無い）。
- カテゴリの表示色は、パレット（`src/config/colorPalette.ts` の `SWATCH_COLORS`）から1つ選ぶ。各スウォッチはライト/ダークの色ペアを持ち、テーマに応じて切り替わる。新規作成時は使用数が最も少ない色が初期選択される。円グラフの色分けや取引行のドットに使われる。
- **入力制約**（カテゴリ編集モーダルの保存時）: カテゴリ名は必須で、同じ収支種別内で重複不可。サブカテゴリ名は空不可・同一カテゴリ内で重複不可。
- 保存はモーダルの「追加 / 更新」ボタンで確定し、Firestore への書き込み完了を待たずにモーダルを閉じる（失敗時は後から赤の通知が出る）。
- カテゴリを削除・リネームしても、既存の取引データが保持しているカテゴリ名は変わらない（過去データは元の文字列のまま残る）。
  - **削除時**: 確認ダイアログを表示し、そのカテゴリを使う取引が存在すれば件数と「取引は削除されず、カテゴリ名のまま残る（色はニュートラル表示になる）」旨を併記する。件数は通常取引のみで、**定期取引は数えない**。
  - **リネーム時**: 旧名を使う取引が存在すれば「N件の既存取引は旧カテゴリ名「〜」のままです」と警告通知（黄）を出す。取引側・定期取引側の一括リネームは行わない。
- 設定の保存に失敗した場合は「設定の保存に失敗しました。もう一度お試しください。」（赤）を表示する。

### 3.2 役割（CategoryRole）による集計判定

金額の集計は**「投資」「給与」といった特定のカテゴリ名を集計コードに埋め込むのではなく、カテゴリ/サブカテゴリに付与された「役割」**で判定する。これにより、ユーザーがどんな名前のカテゴリを作っても役割さえ付ければ集計対象になる。

ただし役割の検索キーは**現在の設定にあるカテゴリ名**であり、取引側はカテゴリ名の文字列を保持している。そのため、**カテゴリをリネーム・削除すると、旧名のまま残っている過去取引は役割判定から外れ、過去月の投資額・貯蓄率・支出集計が変わり得る**（[`基本仕様書.md`](./基本仕様書.md#15-既知の課題今後の検討事項) #10）。リネーム時の警告通知（[3.1](#31-カテゴリ管理)）はこのための注意喚起である。

| 役割 | 集計への影響 |
|---|---|
| `salary_income`（給与収入） | 貯蓄率の分母になる。額面年収推定の対象になる。給与・賞与にのみ付与し、配当等には付けない運用を想定 |
| `investment`（投資） | 支出集計から除外し、年間投資額として別集計する |
| `advance_payment`（立替金） | 支出集計から除外する |
| `advance_repayment`（立替回収） | 収入集計から除外する |
| `exclude_from_pace`（支出ペース除外） | 支出ペースチャートの対象から除外する（家賃など毎月一定額の固定費向け） |

役割はカテゴリとサブカテゴリの両方に付与でき、いずれか一方に付いていれば該当役割ありと判定する（OR 条件）。役割の説明文はカテゴリ編集画面にも表示される。

### 3.3 集計ルールの実体

`createTransactionRules(settings)` が上記の役割マップから判定関数一式（`isInvestment` / `isSalaryIncome` / `isExcludedFromExpense` など）を生成し、`SettingsContext` を通じてアプリ全体に配布する。**月次集計（ホーム画面の収支・KPI）とカテゴリ別グラフ、CSV取り込み時のフラグ再導出**はこの判定関数一式を使う。

一方で、以下の画面は同じ役割情報を参照しつつも、判定関数の一部（`isInvestment` / `isAdvancePayment` / `isAdvanceRepayment` など）のみを個別に使っており、`affectsExpense === false` の取引まで除外する完全な `isExcludedFromExpense` / `isExcludedFromIncome` は適用していない。

- カレンダーの日別収支（[7.2](#72-カレンダー表示) 参照）: 投資・立替のみを除外
- 履歴タブのリスト表示の合計値（[7.1](#71-リスト表示) 参照）: 除外ルールを適用せず、収入・支出をそのまま合算する単純合計

そのため、月次集計の「支出」とこれらの画面の合計値は、投資・立替金以外の除外設定（`affectsExpense === false` の取引がある場合など）によって一致しないことがある。

## 4. 支払方法・カード還元ポイント

### 4.1 支払方法設定

- 支払方法（現金・クレジットカード）を自由に追加・編集・削除できる。削除時は確認ダイアログを表示し、その支払方法を使う取引があれば件数と「取引は削除されず、支払方法名のまま残る」旨を併記する（件数は通常取引のみで定期取引は数えない）。
- 各支払方法に「現金扱い」フラグ、還元率（%）、表示色（**単色**。カテゴリと異なりライト/ダークの切り替えは無い）を設定する。
- **入力制約**: 名前は必須・重複不可。還元率は 0〜100% で入力し、内部では小数（1% = 0.01）で保存する。現金扱いをオンにすると還元率は 0 に固定される。
- 還元ポイント（[4.2](#42-還元ポイント計算)）は表示のたびに現在の設定から再計算するため、**支払方法の削除・リネーム・還元率変更は過去月のポイント表示にも遡って影響する**。
- 「現金扱い」フラグは、取引の `transactionType`（`normal` / `card_payment`）の判定と、還元ポイント計算の対象可否（[4.2](#42-還元ポイント計算) 参照）に使われる。支出の月次集計への計上タイミングは現金・カードで変わらない（いずれも取引日の月に計上する。[2.4](#24-クレジットカード払いの会計モデル重要な業務ルール) 参照）。

### 4.2 還元ポイント計算

- 対象: `type === 'expense'` かつ、還元率が設定された非現金の支払方法を使った取引。
- 計算式: `ポイント = floor(取引金額 × 還元率)`（1件ごとに切り捨て、合算）。
- 集計単位: 選択月ごとに支払方法別のポイント・利用金額を集計し、合計ポイントをホーム画面のKPIタイルに表示する。
- 詳細（カード別の内訳）はKPIタイルタップで開くモーダル（`CardRewardsDisplay`）で確認できる。
- **注意**: この計算は支出集計の除外ルール（投資・立替金・`affectsExpense === false` など）を考慮しない。カード払いであれば、投資目的の支出（`investment` 役割）であっても還元ポイントの対象になる。

## 5. 月間予算・支出ペース

- 設定画面で1ヶ月あたりの予算額（円）を設定できる。保存ボタンは無く、入力が止まってから 600ms 後に自動保存する（デバウンス）。正の有限値のみ保存し、小数は切り捨てる。初期値は 100,000 円。
- ホーム画面の「支出ペースチャート」で、選択月の日次累積支出と、予算に基づく理想ペース（日割り線）を重ねて表示する。
- 集計対象からは、投資・立替金など月次集計と共通の除外対象（`isExcludedFromExpense`）に加えて、`exclude_from_pace` 役割が付いたカテゴリ/サブカテゴリの支出も除外する（毎月同額発生する家賃等でグラフのノイズを減らすため）。
- **理想ペース線**: `(月間予算 ÷ 当月の日数) × 経過日数` で日ごとの直線を引く。
- **実績線**: 対象取引を日別に合算した累積支出。選択月が当月の場合は当日までのみ実績値を描画し、それ以降の未来日は値を持たない（グラフ上で途切れる）。選択月が過去月の場合は月末まで実績値を描画する。
- 予算消化率は、実績線の最終値（直近時点の累積支出）÷ 月間予算で計算する。

## 6. ホーム画面（ダッシュボード）

選択中の月についての要約画面。上から以下の順に構成される。

1. **月次ナビゲーション**: 前月/次月ボタン、モバイルはスワイプ操作にも対応。
2. **定期取引の通知**: 実行日を過ぎ、かつ今月まだ記録されていない有効な定期取引があれば、通知カードとして一覧表示する（[8. 定期取引](#8-定期取引) 参照）。
3. **収支バンド**:
   - 今月の収支（ヒーロー数値、収入−支出）と前月比（トレンド矢印 + %）
   - 収入合計・支出合計とそれぞれの前月比
4. **KPIタイル**（3列）:
   - **貯蓄率**: `年間投資額 ÷ 年間給与収入 × 100`（選択中の年ベース）。タップで詳細モーダル。
   - **獲得ポイント**: 選択月のカード還元ポイント合計。タップでカード別内訳モーダル。
   - **年間投資額**: 選択中の年の投資額合計。タップで投資履歴モーダル。
5. **チャート**:
   - 支出内訳・収入内訳（円グラフ、カテゴリ/サブカテゴリ別）
   - 支出ペースチャート（[5.](#5-月間予算支出ペース) 参照）
   - カテゴリ別支出推移（折れ線グラフ、比較対象カテゴリは設定でカスタマイズ可能。未設定時は支出上位3カテゴリを自動選択）
6. 年間振り返りへのショートカットリンク。
7. バージョン表示。

前月比較は「前月データが存在する場合のみ」表示する（データ範囲外の月で意味のない+100%などを出さないため）。トレンドの符号は差分そのもので判定し、パーセンテージの分母には前月値の絶対値を使う（マイナス月を基準にした際の符号反転を防ぐ）。

## 7. 履歴（リスト / カレンダー）

`/history` タブ。選択中の月の取引を、画面上部の切り替えで「リスト」表示と「カレンダー」表示の2通りに切り替えられる。

### 7.1 リスト表示

- 選択月の全取引を日付順に一覧表示。
- 各行をタップすると編集モーダルが開く。
- 画面上部に表示する収入・支出の合計は、表示中のフィルター（すべて/収入/支出）に該当する取引を役割による除外なしに単純合算した値。投資・立替金を含む点でホーム画面の月次集計とは異なりうる（[3.3](#33-集計ルールの実体) 参照）。

### 7.2 カレンダー表示

- 月グリッド（42マス固定、前後月の日付も薄く表示）。
- 各日に取引があれば、収入/支出のドット表示と日別収支（±金額、絶対値1万円以上は「◯k」形式に短縮）を表示する。
- 日別収支は投資・立替を除外して計算する（日々の増減として見たくない項目のため）。
- 日付タップで下部に日別内訳（当日の取引一覧）を展開し、前日/翌日ボタンで内訳を開いたまま日付を移動できる（移動範囲は表示中の42日グリッド内）。
- スワイプ操作、または画面上部の矢印ボタンで月を移動できる。
- カレンダーは取引フォームの日付選択（`isSelector` モード）にも同一コンポーネントを再利用している。

## 8. 定期取引

毎月決まった日に発生する取引（家賃・積立投資など）を事前登録し、実行日以降にワンタップで記録する機能。

### 8.1 登録・管理

設定画面から「定期取引」の管理画面を開き、以下を行う。

| 操作 | 内容 |
|---|---|
| 新規追加 | 名前・金額・カテゴリ・サブカテゴリ・支払方法・実行日（1〜31）を入力して保存 |
| 編集 | 全項目を編集可能 |
| 削除 | 完全削除（Firestore からも削除） |
| 有効/無効切替 | トグルスイッチ。無効化するとダッシュボードの通知対象から外れる（データは残る） |

### 8.2 ダッシュボードでの提示条件

以下をすべて満たす定期取引を、ホーム画面の通知カードに表示する。

1. 有効（`isEnabled: true`）である。
2. 当日が実行日（`dayOfMonth`）以上である。実行日が当月の実日数を超える場合（例: 31日設定の2月）は、月末日を実効日とみなす。
3. 今月まだ「記録済み」とみなされる取引が存在しない。判定は、取引日が今月であり、かつカテゴリ・金額・サブカテゴリが一致し、さらに取引の説明（description）に定期取引名が含まれる取引の有無で行う（説明が空の古いデータでは金額・カテゴリの一致のみで緩く判定する）。**支払方法は判定条件に含まれない**（支払方法だけを変えて記録した場合も「記録済み」とみなされる）。

### 8.3 記録操作

1. 通知カードの「記録する」をタップすると確認モーダルが開く。
2. 金額・カテゴリ・サブカテゴリ・支払方法は編集可能、日付は実行日で固定（編集不可）、メモは空欄から入力できる。
3. 「記録する」を押すと、実行日の日付で通常の取引として1件作成する（`type: 'expense'` 固定）。
4. 重複防止のロジックは持たず、同じ定期取引から複数回記録することも操作上は可能（[8.2](#82-ダッシュボードでの提示条件) の判定により、記録済みなら次回以降は通知に出なくなる）。

## 10. 額面年収の推定

アプリが記録するのは口座に着金した金額（手取り）のみで、控除額そのものは記録しない。年間振り返りの「額面」は、手取りから額面を逆算する推定値である。

### 10.1 計算方法

- 「額面 → 手取り」を計算する関数（社会保険料・所得税・住民税の控除ロジック）を実装し、二分探索でこれを反転させることで「手取り → 額面」の概算値を求める。
- 対象となる収入は、役割 `salary_income` を付与したカテゴリ/サブカテゴリの収入のみ（配当など他の役割に属さない収入は対象外）。
- 料率・控除額は年分ごとのテーブル（`src/utils/tax/rates.ts`）に集約されており、税制改正（2025年・2026年の「年収の壁」改正など）があった年は個別のテーブルとして追加する。

### 10.2 前提条件（推定の精度に関わる制約）

- 協会けんぽ（全国平均）・一般の事業・40歳未満・扶養なしを前提とする。
- 含まないもの: 介護保険料（40歳以上）、扶養控除、配偶者控除、生命保険料控除、住宅ローン控除、iDeCo、ふるさと納税、財形貯蓄・社宅費等の給与天引き。
- 住民税は本来前年所得に対する課税だが、本推定では同一年の所得に対して計算する。
- 正確な額面は源泉徴収票の「支払金額」を参照する必要がある旨を画面上に注記する。

## 11. CSV エクスポート / インポート

ヘッダーメニューから実行する。月1回程度のバックアップ運用を想定。

### 11.1 エクスポート

- 全取引を CSV（UTF-8, BOM付き）でダウンロードする。
- 列: 日付・種別（収入/支出）・カテゴリ・サブカテゴリ・金額・メモ・支払方法。
- 数式インジェクション対策として、`=`, `+`, `-`, `@`, タブ, 復帰の文字で始まるフィールドの先頭に `'` を付与する（RFC 4180 のダブルクォートエスケープと併用）。

### 11.2 インポート

- ファイル先頭の1行は無条件にヘッダー行として読み飛ばす。列名や列数の検証は行わない（列の並びが [11.1](#111-エクスポート) のエクスポート形式と一致している前提）。
- 各データ行は1行ずつパースする（ダブルクォート内のカンマ・エスケープされた `""` に対応）。

| 検証項目 | 内容 |
|---|---|
| ファイルサイズ上限 | 2MB |
| 行数上限 | 5,000行（超過分は打ち切り、`truncated` フラグで通知） |
| メモの文字数上限 | 200文字（超過分は切り詰め） |
| カテゴリ/サブカテゴリ/支払方法の文字数上限 | 50文字（超過分は切り詰め） |
| 金額 | 整数・0より大きい・10億円以下でなければスキップ |
| 日付 | 1970-01-01〜2100-12-31の範囲外、またはパース不能ならスキップ |
| 種別 | 「収入」「支出」以外はスキップ |
| カテゴリ空欄 | スキップ |

- 無効な行は取り込まず、行番号と理由を一覧で返す（`skippedRows`）。
- **カテゴリ列**の値が設定に存在しない名前の場合、取り込みは行うが警告として一覧で返す（`unknownCategories`）。役割ベースの集計に乗らない旨をユーザーに提示するため。**この警告はカテゴリ列のみを対象とし、サブカテゴリ・支払方法の未登録は警告しない**。
  - 照合に使う「既知の名前」はカテゴリ名とサブカテゴリ名を合わせた集合なので、カテゴリ列の値が既存のサブカテゴリ名と一致する場合は警告されない。
  - 設定にカテゴリが1つも無い場合は警告自体を行わない。
- 取り込み時、`transactionType` / `affectsExpense` は現在の設定ルールから再導出する（エクスポート→インポートの往復で支出が二重計上されないようにするため）。
- エクスポート時に付与した数式インジェクション対策の `'` は、インポート時に取り除く（往復で値が変化しないようにする）。
- 書き込みは Firestore の `writeBatch` で **500件ずつ**コミットする。途中のバッチが失敗した場合、それ以前のバッチは確定済みのため**部分的に取り込まれた状態**になりうる（ロールバックしない）。
- **既存取引との重複チェックは行わない**（常に追記）。同じ CSV を2回取り込むと取引が二重になる。
- **往復で失われる情報**: 取引 ID・作成/更新日時は再生成される。改行を含むメモはエクスポートではダブルクォートで囲まれるが、インポートは行単位（`\r?\n` で分割）で解析するため正しく復元できない。CSV はバックアップとしては不完全である（[`基本仕様書.md`](./基本仕様書.md#117-バックアップリストア) 参照）。
- 結果の通知: 取り込み件数を表示し、スキップ行・打ち切り・未知カテゴリがあれば黄色の通知で内訳を併記する（10秒表示）。有効行が0件なら「有効なデータが見つかりませんでした」（赤）。読み込み・解析・書き込みのいずれかで例外が起きた場合は「ファイルの読み込みに失敗しました」（赤）にまとめる。

## 13. 月次ナビゲーション・タブ遷移

- ホーム・履歴の各画面上部にある年月表示から、前月/次月ボタン（モバイルはスワイプも可）で月を切り替える。

- 振り返り・設定タブは月の状態を持たない（`carriesMonth: false`）。
- タブの選択状態は URL パスが正であり、ブラウザの戻る操作で前のタブに戻れる。

## 15. テーマ切替（ライト / ダーク）

- ヘッダー右側の太陽 / 月アイコンでライト⇄ダークを切り替える。
- 初期値は OS の配色設定に追従する（Mantine の `defaultColorScheme="auto"`）。
- ユーザーが明示的に切り替えた値はブラウザの `localStorage`（Mantine 既定のカラースキームマネージャ）に保存され、同じ端末・ブラウザ内で維持される。**デバイス間では同期しない**（グラフ設定と異なり、設定ドキュメントには保存しない）。
- 切り替え判定には `useComputedColorScheme` を使い、`auto` を実際の light / dark に解決してから反転する（`auto` のまま `'dark'` と比較すると、OS がダークのとき初回タップで何も起きない）。
- OS のステータスバー色（`theme-color`）はライト `#f5f6f8` / ダーク `#131417` を `prefers-color-scheme` で出し分ける。
- カテゴリ・支払方法の色はライト / ダークの2色をユーザー設定に持ち、現在のテーマに応じて `getColor(name, isDark)` で解決する。

## 16. PWA インストール案内

- ブラウザが `beforeinstallprompt` を発火した場合（主に Android Chrome / デスクトップ Chrome・Edge）、「アプリをインストール」モーダルを表示する。iOS Safari はこのイベントを発火しないため、モーダルは出ない（ユーザーが共有メニューから手動で追加する）。
- 「インストール」でブラウザ標準のインストールプロンプトを呼び出す。「後で」を選ぶと `localStorage` の `pwa-dismissed` に時刻を記録し、**24時間は再表示しない**。
- 既にスタンドアロン表示（`display-mode: standalone`）で起動している場合、または `appinstalled` を受け取った後は表示しない。
- Service Worker の登録もこのコンポーネントが担う（本番のみ登録、開発時は登録解除。キャッシュ戦略は [`基本仕様書.md`](./基本仕様書.md#113-レスポンシブ--pwa) 参照）。
- **既知の問題**: モーダル内の説明文「オフラインでも基本機能が利用可能」「プッシュ通知対応」は現時点の実装と一致しない（オフライン動作は保証しておらず、再起動後はデータを表示できない。プッシュ通知の機能は無い）。オフライン対応は [Issue #126](https://github.com/kakawo18/kakeibo-app/issues/126) で今後実装する。プッシュ通知はスコープ外のため文言を削除する方向で別途対応する（[`基本仕様書.md`](./基本仕様書.md#15-既知の課題今後の検討事項) 参照）。

## 17. 共通仕様（通知・確認ダイアログ・ローディング）

### 17.1 通知（トースト）

Mantine `notifications` を使い、画面端に一時表示する。色で結果を区別する。

| 色 | 用途 | 例 |
|---|---|---|
| 緑 | 操作の成功 | 取引を追加しました / エクスポート完了 |
| 赤 | 操作の失敗 | 〜に失敗しました。もう一度お試しください。 |
| 黄 | 成功したが注意がある | カテゴリ名を変更しました（既存取引は旧名のまま） / インポート完了（スキップ行あり） |

- 表示時間は Mantine 既定。注意事項を含むインポート結果のみ 10 秒に延長する。
- 失敗通知は原因を特定せず、再試行を促す定型文にする（Firebase のエラー内容をそのまま出さない）。CSV インポートのみ「ファイルの読み込みに失敗しました」に統一している。

### 17.2 確認ダイアログ

取り消せない操作は Mantine `modals.openConfirmModal` で確認を挟む。確認ボタンは赤、ラベルは「削除」/「キャンセル」。

| 操作 | 確認あり |
|---|---|
| 取引の削除 | ✓ |
| カテゴリの削除 | ✓（使用中の取引件数を併記） |
| 定期取引の削除 | ✓ |
| 支払方法の削除 | ✓（使用中の取引件数を併記） |
| 取引・設定の保存、定期取引の有効/無効切替 | なし（即時反映） |

### 17.3 ローディング・空状態

- 認証状態の確認中は「読み込み中...」、ログイン後は設定と取引の両方が揃うまで「データを読み込み中...」を全画面で表示し、中身を描画しない。設定が揃う前に描画すると役割判定がすべて false になり集計が静かにずれるため。
- 取引フォーム・定期取引フォーム・定期取引の記録確認は、送信中にボタンをローディング状態にして二重送信を防ぐ。設定画面のカテゴリ / 支払方法の編集モーダルにはこの制御は無く、ボタン押下で即座に閉じる。
- 取引が0件の月でもホーム・履歴は表示され、合計は0円、グラフは空になる。専用のオンボーディング画面は無い。

### 17.4 入力・表示の共通ルール

- 金額は円の整数。表示は `¥` + 3桁区切り、収入は `+`、支出は `-` を前置する。
- 日付は `dayjs` で扱い、表示は日本語形式（`formatDateJa`）。月の判定・表示はいずれも**端末のローカルタイムゾーン**で行い、JST に固定していない。
- モバイルの入力欄はフォント16px以上（iOS のズーム防止）、タップ領域48px以上。
- モーダルの z-index は 200。ヘッダー・タブバー（100）、FAB（150）より上に出る。
