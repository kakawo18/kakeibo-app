# Claude 連携 書き込み機能 実装手順書（計画）

- 状態: 計画（未実装）
- 作成: 2026-10-26
- 仕様: [書き込み仕様書.md](./書き込み仕様書.md)（先に読む）
- 読み取りの実装の手順と教訓: [手順書.md](./手順書.md)

この手順書は、書き込み仕様書で決めた機能を、どの順に作り、各段階をどう確かめるかを書いたものである。読み取りの実装（手順書.md）で整えた認可サーバー・MCP の受け口・エミュレータのテストの上に積むので、そちらで説明したことは繰り返さない。

## 1. 進め方

作業は3つの PR に分ける。どの PR も、環境変数 `MCP_WRITE_ENABLED` を登録するまでは本番の振る舞いを変えない。途中で止めても本番は壊れない。

| PR | 内容 | 利用者に見える変化 | バージョン |
|----|------|--------------------|------------|
| 1 | 書き込み層（`kakeiboWriter.ts`）・入力の検査・確認トークン・二重登録の判定 | なし | 上げない |
| 2 | scope `kakeibo.write`・同意画面・メタデータ・リフレッシュの scope の検査 | なし（`MCP_WRITE_ENABLED` が無い間） | 上げない |
| 3 | 4つのツール・サーバーの説明文・ドキュメントの更新 | `MCP_WRITE_ENABLED=1` で書き込みが使えるようになる | v6.12.0 |

どの PR でも、コミットの前に次を通す（AGENTS.md の決まり）。

```bash
npm run lint
npm run type-check
npm test
npm run test:emulator   # Java 21 が必要
npm run build
```

PR 3 の後に、人が行う作業（2章）と本番での確認（6章）がある。

## 2. 人が行う作業

利用者が行う作業は、PR 3 が本番に入った後の4つである。作業の前に、Claude が「PR 3 をマージしました」と知らせる。

### 2.1 Vercel に `MCP_WRITE_ENABLED` を登録する

1. Vercel でプロジェクト `kakeibo-app` を開き、「Settings」→「Environment Variables」を選ぶ。
2. Key に `MCP_WRITE_ENABLED`、Value に `1` を入れる。
3. Environments は「Production」だけにチェックを入れる（Preview と Development は外す）。
4. 「Save」を押す。
5. 「Deployments」を開き、いちばん上の Production のデプロイの「⋯」→「Redeploy」を押す。環境変数は再デプロイしないと反映されない。
6. デプロイが「Ready」になったら、Claude に知らせる。Claude がメタデータ（`/.well-known/oauth-protected-resource`）に `kakeibo.write` が出ていることを確かめる。

### 2.2 claude.ai でコネクタを接続し直す

今の接続は読み取りの許可しか持たない（仕様書 8.3 節）。書き込みの許可を付けるために、接続をやり直す。

1. claude.ai を開き、「カスタマイズ」（Customize）→「コネクタ」（Connectors）で家計簿のコネクタを開く。
2. 「切断」（Disconnect）を押す。コネクタそのものは削除しない（URL と Client ID を入れ直さずに済む）。
3. 同じ画面で「接続」（Connect）を押す。ブラウザで家計簿の同意画面が開く。
4. 同意画面の「許可すると、Claude は次のことができます」に、「取引の追加と、金額・メモなどの編集」が出ていることを確かめる。出ていなければ、許可せずに Claude に知らせる。
5. パスワードを入れて「許可する」を押す。

画面の名前は Claude の更新で変わることがある。「切断」が見つからない場合は、コネクタを削除して追加し直す（手順書.md 6.1 節）。

### 2.3 家計簿の設定画面で古い接続を解除する

claude.ai で切断しても、家計簿の側には古い接続のトークンが残る（30日使わなければ消える）。

1. 家計簿アプリの「設定」→「Claude との接続」を開く。
2. 接続が2つ並ぶ。「いつ許可したか」が古いほうの「解除」を押す。
3. 新しいほうが残っていることを確かめる。

### 2.4 claude.ai の個人設定に、自分だけの決まりを書く

遊びの日の合計の記録先は利用者ごとの決まりなので、サーバーではなく claude.ai に書く（仕様書 7章）。claude.ai の設定の個人設定（「Claude に知っておいてほしいこと」などの欄）に、次の文を足す。画面の名前は実装の時点で確かめ、この節を書き直す。

```text
家計簿のコネクタで、遊びの日などに金額を続けて送ってから「記録して」と言ったときは、
合計を「交際費」「現金」の1件として記録する。メモには内訳を書く。
```

## 3. PR 1: 書き込み層

### 3.1 作るもの

| ファイル | 内容 |
|----------|------|
| `src/server/kakeiboWriter.ts` | 取引の作成（ID を指定して作り、同じ ID があれば失敗する）と部分更新。uid を最初の引数で受け取る。更新の前に `userId` を確かめる |
| `src/server/mcp/transactionDraft.ts` | 入力の検査と整え（仕様書 6章）。設定を受け取り、カテゴリ・サブカテゴリ・支払方法・金額・メモ・日付を検査して、書く内容と `accounting` を返す。React・Firebase に依存しない純関数にする |
| `src/server/mcp/confirmationToken.ts` | 確認トークンの発行と検証（仕様書 5.6 節）。`jose` の `SignJWT`・`jwtVerify` を使う |
| `src/server/mcp/duplicates.ts` | 二重登録の判定（仕様書 5.7 節）。その日の取引の一覧を受け取る純関数 |

日付は `src/server/mcp/dates.ts` の `parseDay`（その日の0時）を使い、今日なら記録した時刻に替える。集計のフラグは `createTransactionRules(settings)` の `deriveTransactionFlags` と、`resolveFlagsOnEdit` をそのまま呼ぶ。

確認トークンの鍵は、`MCP_TOKEN_SECRET` をそのまま使わず、HMAC-SHA256 で用途の名前（`kakeibo-confirm`）から導いた値にする。アクセストークンと鍵を共有しないためで、`typ` と `aud` の違いと合わせて、二つのトークンを取り違えても検証に通らない。

### 3.2 保存の形

`src/data/transactionSerializer.ts` の `toTransactionCreateData`・`toTransactionUpdateData` は、クライアント SDK の `Timestamp` と `deleteField` を作るので、Admin SDK から書けない（手順書.md 10.7 節）。次のどちらかにする。

- 規則の部分（空のサブカテゴリを書かない、メモは空でも書く、など）を SDK に依存しない関数に切り出し、クライアントとサーバーの両方から使う。
- サーバー用に同じ規則の関数を作り、エミュレータのテストで形が同じことを確かめる。

前者のほうが規則のずれが起きにくい。切り出しがアプリの画面のコードを大きく変える場合だけ、後者にする。

### 3.3 テスト

単体のテスト（`*.test.ts`）:

- 入力の検査: 存在しないカテゴリ・アーカイブしたカテゴリ・別のカテゴリのサブカテゴリ・収入の支払方法・201文字のメモ・0円と上限を超える金額・存在しない日付（2026-02-30）を拒否する。
- 改名したカテゴリ: 改名前の名前で記録された取引に今の名前を渡すと、変更なしになる。
- カテゴリを変えてサブカテゴリを指定しないと、サブカテゴリを消す。
- `accounting`: 投資・立替金・立替回収の役割のカテゴリで、それぞれの説明になる。
- 確認トークン: 改ざん・期限切れ・別の uid・アクセストークンを渡したときに拒否する。アクセストークンの検証に確認トークンを渡しても拒否する。
- 二重登録: 同じ日・同じ金額・同じ種類だけが当たり、金額か種類が違えば当たらない。

エミュレータのテスト（`src/server/kakeiboWriter.emulator.test.ts`）:

- 作成した取引を `fromTransactionDoc` で読むと、渡した内容と一致する。
- 作成した取引と同じ内容を、同じ利用者としてクライアント SDK から作っても、`firestore.rules` に通る（ルールと同じ基準で書いていることの確認）。
- 同じ ID で2回作ると、2回目は失敗し、1件のまま。
- 他人の取引の ID で更新すると、「見つからない」と同じ結果になり、取引は変わらない。
- サブカテゴリを空にする更新で、フィールドが消える（`deleteField` と同じ結果）。
- サーバーで作った取引を、アプリと同じクライアント SDK の `updateTransaction` で更新できる。

## 4. PR 2: 認可の変更

### 4.1 変えるもの

| ファイル | 変更 |
|----------|------|
| `src/server/config.ts` | `isMcpWriteEnabled()`（`MCP_WRITE_ENABLED === '1'`） |
| `src/server/oauth/params.ts` | scope の一覧を `kakeibo.read`・`kakeibo.write` にする。書き込みが無効なら `kakeibo.read` だけ。省いたときの与え方（仕様書 8.1 節） |
| `src/server/oauth/metadata.ts` | `scopes_supported` を有効な scope の一覧にする |
| `src/app/.well-known/oauth-protected-resource/route.ts` | 保護リソースのメタデータにも `scopes_supported` を載せる。mcp-handler の `protectedResourceHandler` は載せられないので、`generateProtectedResourceMetadata` で同じ内容を組み立てて返す |
| `src/server/oauth/tokenEndpoint.ts` | リフレッシュで、最初に許可した scope を超える指定を `invalid_scope` で拒否する |
| `src/server/oauth/verifyMcpToken.ts` | 開発用の省略（`MCP_DEV_UID`）の scope に、書き込みが有効なら `kakeibo.write` を足す |
| `src/app/oauth/authorize/page.tsx`・`src/features/claude-connect/ConsentScreen.tsx` | 同意の scope を画面に渡し、書き込みを含むときの文言を出す（仕様書 8.2 節） |

認可コード・リフレッシュトークンのドキュメントには、すでに `scope` が保存されている。新しい項目は要らない。

### 4.2 テスト

- `MCP_WRITE_ENABLED` が無いとき、scope の扱い・メタデータ・同意画面が v6.11.2 と同じ（今のテストがそのまま通る）。
- 有効なとき: scope を省くと両方が与えられる。`kakeibo.write` だけを求めると `kakeibo.read` も足される。知らない scope は拒否する。
- リフレッシュ: `kakeibo.read` だけの接続で `kakeibo.read kakeibo.write` を求めると拒否する（エミュレータのテスト）。
- 同意画面: Playwright でスマホ幅のスクリーンショットを撮り、書き込みの文言が切れずに出ることを確かめる。

## 5. PR 3: ツールと説明文

### 5.1 作るもの

1. `src/server/mcp/tools.ts` に4つのツールを足す（仕様書 5章）。`isMcpWriteEnabled()` のときだけ登録する。書き込みのツールは、処理の最初に `ctx.http?.authInfo?.scopes` に `kakeibo.write` があるかを確かめる。
2. `src/server/mcp/instructions.ts` の説明文を、書き込みが有効なときは仕様書 7章の内容に替える。最初の行の「読み取り専用で提供する」も書き換える。
3. ツールの説明文（description）に、確認のツールを先に呼ぶこと、記録のツールは利用者の承認の後に呼ぶことを書く。説明文は Claude がツールを選ぶ手がかりなので、サーバーの説明文と重ねて書いてよい。
4. ドキュメント: README・仕様書・利用者向けのガイド・AGENTS.md を、書き込みがある前提に直す（仕様書 13章）。書き込み仕様書と書き込み手順書の「状態」を書き換える。
5. v6.12.0 にし、CHANGELOG に書く。

### 5.2 ローカルで確かめる

開発サーバーとエミュレータで、`.env.local` に `MCP_WRITE_ENABLED=1` を足して動かす（手順書.md 4.5 節の方法）。curl か MCP Inspector で次を確かめる。

- `tools/list` に4つのツールが出て、確認のツールに `readOnlyHint: true`、記録のツールに `readOnlyHint: false` が付いている。
- 確認 → 記録で取引が1件でき、開いているアプリの画面にすぐ出る。
- 同じ確認トークンで記録を2回呼んでも1件のまま（2回目は `alreadyRecorded: true`）。
- 確認トークンの一部を書き換えると拒否される。
- 編集の確認で変更前と変更後が返り、記録で反映される。メモだけを直したときに、カード払いの扱いが変わらない。
- `MCP_WRITE_ENABLED` を外して再起動すると、4つのツールが一覧から消える。

### 5.3 書き込み仕様書 11章の確認

PR 3 を本番に出した後、2章の作業のときに次を確かめ、結果を書き込み仕様書に書き足す。

- 2.2 節の同意画面の URL に `scope` が付いているか（付いていれば、その値）。
- 記録のツールを呼ぶ前に、claude.ai が承認を求めるか。
- 接続し直した後の新しい会話で、4つのツールが使えるか。

## 6. 本番での確認

2章の作業の後、claude.ai の新しいチャットで次を順に試す。数字が確かめやすいよう、確認の後は家計簿アプリで記録を見る。試した記録は最後にアプリから削除する。

| 試すこと | 期待する結果 |
|----------|--------------|
| 「今日のランチ 1,200円、現金で食費に記録して」 | 確認の内容が出て、応答が止まる。「OK」で記録される。アプリにすぐ出る |
| もう一度同じことを頼む | 確認に二重登録の警告が出る。「やめる」と言えば記録されない |
| レシートの写真を送って「記録して」 | 合計・日付・店名を読み取った確認が出る。支払方法が読めなければ聞かれる |
| 「ランチ 1,200」「カラオケ 2,000」「夕食 2,200」と3回送り、「記録して」 | 送るたびに途中の合計が返る。最後に交際費・現金・5,400円・内訳のメモで確認が出る |
| 「さっきのランチを1,300円に直して」 | 変更前（1,200円）と変更後（1,300円）が並んで出る。「OK」で直る |
| 確認の内容を見て「やめて」と言う | 何も書かれない |
| 「さっきのランチを削除して」 | 削除はできないので、アプリから消すよう案内される |
| スマホの Claude アプリで、上の1つ目を試す | Web と同じに動く |

## 7. 運用

### 7.1 止めたいとき

| したいこと | 方法 |
|------------|------|
| 書き込みだけを止める | Vercel の `MCP_WRITE_ENABLED` を消して再デプロイする。4つのツールが消え、読み取りはそのまま使える |
| Claude 連携のすべてを止める | 今と同じく `MCP_ENABLED` を消して再デプロイする（手順書.md 8.1 節） |

### 7.2 うまくいかないとき

| 症状 | 確かめること |
|------|--------------|
| 「この接続には記録の許可がありません」と出る | 接続し直していない（2.2 節）。接続し直しても出るなら、同意画面に書き込みの文言が出ていたか、2.1 節の再デプロイが済んでいるかを確かめる |
| 書き込みのツールが Claude から見えない | `MCP_WRITE_ENABLED` が Production に登録され、再デプロイされているか。新しいチャットで試したか |
| 「確認からやり直してください」と出る | 確認から30分を過ぎたか、その間に設定のカテゴリや支払方法を変えた。Claude にもう一度確認させる |
| アプリの画面と記録の内容が違う | 記録の形がアプリとずれている。PR 1 のエミュレータのテストが通っているか、`fromTransactionDoc` での読み戻しを確かめる |
| チャットでの承認と claude.ai の承認の両方が要って煩わしい | チャットの承認だけにしたければ、claude.ai の設定で記録のツールを「常に許可」にする（書き込み仕様書 4.3 節の注意を読んでから） |
